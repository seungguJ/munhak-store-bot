# 선학역 행사 알림 앱 — 설계 (munhak-store-bot 확장판)

작성일: 2026-10-10

## 1. 목적

선학역 근처 세븐일레븐 사장님이 주변 콘서트·행사를 **미리** 알고 발주량을 늘릴 수 있게 한다.
각 행사마다 다음을 알려준다.

- 행사가 있다는 사실 (새로 발표되면 바로)
- 인기 정도와 예상 인파
- 위치 (행사장, 선학역에서의 거리, 지도 링크)
- 발주 추천 (품목, 평소 대비 배수, 수요가 몰리는 시간대)

## 2. 기존 봇과 달라지는 점

| 항목 | 기존 munhak-store-bot | 확장판 |
|---|---|---|
| 받는 사람 | 나 (카카오 "나에게 보내기") | **사장님** (안드로이드 폰) |
| 전달 방식 | 카카오톡 텍스트 | **PWA 웹앱 + 웹푸시** |
| 조사 실행 | 매주 내가 Claude에게 직접 요청 | **Claude Code 루틴이 매일 자동 실행** |
| 행사장 범위 | 문학경기장 | **선학역 반경 2~3km** |
| 핫템 섹션 | 포함 | 1차 범위에서 제외 (나중에 앱 탭으로 추가) |

유지하는 것: KBO 정규리그 제외 기준, KOPIS 수집기(`collectors/munhak_events.py`) 재사용, "AI가 조사하고 repo에 push하면 Action이 전달"하는 구조.

## 3. 전체 구조

```
[Claude Code 루틴 · 매일 06:30 KST · 구독 사용량]
  1. data/events.json 읽기 (기존 행사 목록)
  2. 수집: KOPIS(행사장 목록) + 웹검색(예매처·뉴스·SNS)
  3. 새 행사 / 변경(매진·회차 추가·취소) 판단 → 인기·인파·등급·발주 추천 작성
  4. data/events.json 갱신 (스키마 검증 통과해야 함) → commit & push
        │
        ▼
[GitHub Actions]
  A. on push (data/events.json) → 변경분 푸시: 🆕 새 행사, ⬆️ 등급 상승, ❌ 취소
  B. cron 매일 08:00 KST → 날짜 기반 푸시: D-7, D-1 (Claude 없이도 동작)
        │  web push (VAPID, pywebpush)
        ▼
[사장님 폰 · PWA (GitHub Pages)]
  data/events.json을 읽어 화면 표시
```

**역할을 나눈 이유:** 루틴은 *발견과 판단*만 하고, 날짜 기반 리마인드(D-7/D-1)는 Action이 결정론적으로 보낸다.
루틴이 하루 실패하거나 사용량 한도에 걸려도 이미 등록된 행사의 알림은 끊기지 않는다.

## 4. 행사장 목록 (`data/venues.json`, 고정)

| 행사장 | 선학역 거리(대략) | 권역 | 거리 가중치 |
|---|---|---|---|
| 선학체육관 | 도보권 | 근거리 | 1.0 |
| 선학국제빙상경기장 | 도보권 | 근거리 | 1.0 |
| 선학하키경기장 | 도보권 | 근거리 | 1.0 |
| 문학경기장 주경기장 | ~1.5km | 근거리 | 1.0 |
| SSG랜더스필드 (정규리그 제외) | ~1.5km | 근거리 | 1.0 |
| 문학박태환수영장 | ~1.5km | 근거리 | 0.8 |
| 인천문화예술회관 | ~2.5km | 원거리 | 0.5 |
| 인천시청 애뜰광장 | ~3km | 원거리 | 0.5 |

- 수용인원, 좌표, 정확한 거리는 구현할 때 공식 자료로 확인해서 채운다.
- 목록에 없는 장소의 행사는 저장하지 않는다. 루틴이 새 후보 장소를 발견하면 `venue_suggestions`에만 기록하고, 추가 여부는 사람이 결정한다.

## 5. 데이터 스키마 (`data/events.json`)

```json
{
  "updated_at": "2026-10-10T06:42:00+09:00",
  "events": [
    {
      "id": "kopis-PF123456",
      "title": "PLAVE 월드투어 [인천]",
      "category": "concert",
      "venue_id": "munhak-main",
      "start": "2026-11-14",
      "end": "2026-11-15",
      "show_times": ["18:00"],
      "status": "scheduled",
      "popularity": {
        "sold_out": true,
        "extra_shows": false,
        "evidence": ["멜론티켓 전석 매진 (10/3)", "네이버 검색량 4주 상승"]
      },
      "crowd_estimate": { "per_day": 45000, "fill_rate": 1.0 },
      "grade": "S",
      "peak_hours": ["10:00-13:00 굿즈 대기", "16:00-18:00 입장 전"],
      "order_advice": [
        { "item": "생수·이온음료", "multiplier": 3 },
        { "item": "삼각김밥·김밥", "multiplier": 2 },
        { "item": "보조배터리", "multiplier": 2 }
      ],
      "sources": ["https://..."],
      "first_seen": "2026-09-20",
      "last_changed": "2026-10-03"
    }
  ],
  "venue_suggestions": []
}
```

- `id`: KOPIS가 있으면 `kopis-<mt20id>`, 없으면 `web-<제목+날짜 해시>`
- `status`: `scheduled` | `cancelled` | `done`
- 저장소 안에 `schema/events.schema.json`(JSON Schema)을 두고 루틴과 Action 양쪽에서 검증한다. 검증에 실패하면 루틴은 push하지 않는다.

## 6. 등급 기준 (루틴 프롬프트에 고정)

```
예상 인파(일)  = 수용인원 × 채움률
  채움률: 매진 1.0 / 추가 회차 1.0 / 잔여석 보통 0.7 / 잔여석 많음 0.5 / 무료 행사는 근거 기반 추정
보정 인파      = 예상 인파 × 거리 가중치
등급: S ≥ 30,000 · A ≥ 10,000 · B ≥ 3,000 · C 그 외
```

- Claude는 팬덤 화력, 굿즈 대기 같은 정성적 근거로 **한 단계까지만** 올리거나 내릴 수 있고, 그 사유를 `evidence`에 남긴다.
- 기준값(30,000 등)은 첫 시즌 운영 후 실제 매출과 비교해 보정한다.

## 7. 푸시 알림

| 종류 | 트리거 | 예시 |
|---|---|---|
| 🆕 새 행사 | events.json에 새 id 추가 (B등급 이상) | `🆕 [S] 11/14~15 PLAVE · 문학경기장 · 일 4.5만 명 예상` |
| ⬆️ 등급 상승 / ❌ 취소 | grade 상승 또는 status=cancelled | `⬆️ PLAVE 전석 매진 → S등급` |
| 📦 D-7 | Action cron | `📦 D-7 PLAVE: 생수 3배·김밥 2배 발주 준비` |
| ⏰ D-1 | Action cron | `⏰ 내일 PLAVE · 10시부터 굿즈 대기 인파` |

- C등급은 푸시하지 않고 앱에만 표시한다 (알림 피로 방지).
- 푸시를 누르면 앱의 해당 행사 상세 화면이 열린다.

## 8. PWA 화면

- **홈**: 다가오는 행사 카드 목록 (D-day 순). 카드에 등급 색, 제목, 날짜, 장소, 예상 인파 표시
- **상세**: 지도 링크(네이버 지도), 인기 근거, 수요 시간대, 발주 추천표, 원본 링크
- **설정**: 알림 켜기, 알림 테스트 버튼
- 기술: 정적 HTML/JS + `manifest.json` + Service Worker. 빌드 도구 없이 GitHub Pages로 배포
- 글씨는 크게, 한 화면에 핵심만 (사장님이 매장에서 빠르게 확인하는 용도)

## 9. 푸시 구독 저장

수신자는 사장님 한 명이므로 서버를 두지 않는다.

1. 사장님 폰에서 PWA 설치 → "알림 켜기" → 화면에 구독 정보(JSON)가 표시됨
2. 설치를 도와주는 사람(나)이 그 값을 GitHub Secret `PUSH_SUBSCRIPTIONS`에 등록 (JSON 배열이라 여러 명도 가능)
3. Action이 VAPID 키(`VAPID_PRIVATE_KEY` Secret)로 전송
4. 전송 결과가 404/410(구독 만료)이면 Action 로그와 PWA 화면에 "알림 재등록 필요"를 표시

구독 대상이 늘어나 수동 등록이 불편해지면 Cloudflare Worker로 구독 저장을 옮긴다 (이번 범위 밖).

## 10. 루틴 운영

- `/schedule`로 클라우드 루틴 생성, munhak-store-bot repo 대상, 매일 06:30 KST
- 프롬프트는 repo의 `ROUTINE.md`에 둔다 (조사 순서, 등급 기준, 스키마, 금지사항). 루틴은 이 파일을 읽고 따른다.
- KOPIS 키는 루틴 환경변수로 제공한다. 수집 보조 스크립트 `collectors/`는 루틴이 실행해서 쓴다.
- 지켜야 할 것: 웹검색 결과의 출처 날짜 확인 (오래된 기사를 새 행사로 착각 금지), 정규리그 제외, 행사장 목록 밖 장소 제외
- 실패 감지: `updated_at`이 36시간 넘게 갱신되지 않으면 Action이 나에게 GitHub 이슈를 생성한다 (사장님에게는 보내지 않음)

## 11. 범위 밖 (이번 버전에서 하지 않음)

- 세븐일레븐 핫템 탭
- 매출 기록과 등급 자동 보정
- 날씨 연동 발주 추천
- iOS 지원, 다수 매장 지원

## 12. 테스트

- `collectors/` 행사장 필터: 기존 pytest를 확장
- 스키마 검증: 정상 예시와 깨진 예시 fixture
- 알림 판정 로직(새 행사, 등급 상승, D-7/D-1 계산): 이전/이후 events.json을 입력으로 하는 순수 함수 단위 테스트
- PWA: 로컬에서 실제 안드로이드 Chrome으로 설치하고 테스트 푸시가 오는지 수동 확인
